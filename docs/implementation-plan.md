# 实施计划

## 1. 目标与边界

构建一个现代、紧凑、易读的 aria2 下载工作台，借鉴参考图的导航、工具栏、任务列表和详情面板结构，独立实现视觉及交互。Docker 和 TrueNAS 是首版交付要求，不能推迟到功能完成后再补设计。

本文件同时记录实施方案和当前完成状态。默认面向家庭 NAS 的单管理员、单 aria2 实例场景。项目正式名称为 Aria Station。

## 2. 界面与组件规格

| 区域     | 参考的结构         | 独立设计与行为                                                               |
| -------- | ------------------ | ---------------------------------------------------------------------------- |
| 顶栏     | 产品标题和全局入口 | 独立产品图标、连接状态、设置与账户菜单；不模拟系统窗口按钮                   |
| 左侧栏   | 状态分类与图标     | 约 216–240px；分类计数、当前项高亮、底部设置；暂不显示未实现的 RSS／搜索入口 |
| 工具栏   | 常用图标操作       | 突出“新增任务”，其余使用图标按钮和 tooltip；按选中任务能力禁用操作           |
| 任务表格 | 高密度多列列表     | 约 52px 行高、固定表头、进度条、列宽调整；名称省略时可查看全文               |
| 状态栏   | 总速度与任务数量   | 总下载／上传速度、任务数和连接状态，标明断连后的旧数据                       |
| 详情区   | 底部选中项详情     | 可拖动高度和折叠；概览、文件、Peers／连接按协议展示                          |
| 新增弹窗 | 集中创建入口       | 多行 URL、Magnet、种子上传，预设目录、线程数和限速；支持粘贴与拖放         |

修订视觉方案：纯中性灰背景、白色内容表面、低饱和蓝色强调色、清晰分隔线和小圆角。正文以 14px 为基准，次要信息以 12–13px 为主；不使用渐变、宣传语或装饰性图表。英文为初始界面语言，文案独立管理，后续通过标准 i18n 语言包扩展。避免把列表改成低密度卡片墙。Boxicons 图标统一使用 18–20px；下载、等待、暂停、完成、失败等状态有独立图标，所有纯图标按钮必须有可访问名称。

桌面优先支持 1280px 及以上；768–1279px 收缩导航并隐藏次要列；低于 768px 使用导航抽屉、精简任务行和全屏详情。触屏操作不能依赖 hover。色彩对比以 WCAG AA 为目标，支持键盘选中、焦点可见及 Escape 关闭弹窗。

必须设计空列表、首次连接、加载、连接失败、重连、权限不足、磁盘写入失败和部分批量操作失败状态。移除任务与删除文件不能含糊：首版仅移除任务，不提供删除磁盘文件功能；弹窗明确这一结果。

## 3. 架构与数据契约

采用 TypeScript monorepo，计划目录为 `apps/web`、`apps/server`、`packages/shared`、`deploy/docker`、`deploy/truenas` 和 `docs`。Web 服务同时提供前端静态文件、认证 API、受控 aria2 API 和实时事件接口，浏览器保持同源连接。

### aria2 接入

- 列表使用 `tellActive`、分页 `tellWaiting` 和 `tellStopped`，详情按需请求，避免每次更新拉取所有文件和 Peers。
- 操作覆盖 `addUri`、`addTorrent`、`pause`、`unpause`、`remove`、`removeDownloadResult`、`getFiles`、`getPeers`、`getOption` 和 `changeOption`；全局限速另行使用受控全局选项方法。
- WebSocket 通知触发刷新，运行任务默认每 2 秒轮询一次；非活动页面降低频率，重连使用指数退避。通知不视为完整状态快照。
- 原始状态保留 `active/waiting/paused/error/complete/removed`。BT 做种不能简单等同于“下载中”；以完成字节及种子状态单独显示“做种中”。未知状态显示可诊断信息。
- GID 为引擎任务标识；Magnet 元数据任务通过 `followedBy` 等关系衔接实际下载任务，避免详情丢失或重复计数。
- aria2 数值字符串在边界统一解析；字节、速度和剩余时间共用格式化函数，未知 ETA 不展示伪精确值。
- 批量操作逐项反馈成功或失败，状态刷新后校准；不可盲目重试创建任务以免重复下载。

### 持久化与访问控制

- aria2 管理实时任务与下载文件；SQLite 保存应用设置及已观察到的任务历史。定期持久化历史，重启后对账；已有 aria2 未保留的过去记录无法自动补回。
- aria2 开启输入／保存会话和定期会话保存，验证停止容器后的未完成任务恢复。完成记录不能仅依赖 aria2 的内存结果列表。
- 首次使用设置管理员账号，密码使用成熟密码哈希方案。会话 Cookie 使用 HttpOnly、SameSite，并在 HTTPS 下启用 Secure；写操作验证来源／防 CSRF，登录限速。
- RPC secret 仅由服务端读取；日志屏蔽凭据、敏感 URL 查询参数和下载认证信息。RPC 代理采用方法和选项白名单，不提供任意请求转发接口。
- 下载目录使用管理员预设根目录和受控子目录，阻止路径穿越及任意绝对路径。连接已有 aria2 时，路径指向远端引擎文件系统，UI 不声称是 Web 容器本地路径。
- 上传种子设置大小上限并验证格式；站点认证头等敏感高级选项后续开放前单独定义存储规则。

## 4. Docker 和 TrueNAS 交付契约

默认双容器：Web 容器运行应用，aria2 容器运行下载引擎。只将 Web 端口（默认 55290）绑定宿主机；aria2 RPC 6800 仅用于内部网络。55290 位于 IANA 动态／私有端口范围，作为本项目的默认 Web 管理端口，不复用常见 HTTP proxy 或下载器管理端口；实际宿主机映射始终可配置。BT／DHT 入站端口单独配置，并明确防火墙与路由器映射不由应用自动完成。

镜像采用多阶段构建、固定依赖与基础镜像版本，以非 root 用户运行，支持可配置数值 UID／GID。Docker 目标架构为 linux/amd64 和 linux/arm64；TrueNAS 以实际可用的 amd64 主机验证。不会通过特权模式或挂载 Docker socket 实现普通下载功能。

持久化分为应用数据、aria2 配置／会话和下载目录三个挂载点。Web 服务默认不挂载下载 dataset；磁盘写权限由 aria2 承担。启动时输出可操作的目录不可写诊断，不默认递归 chown 用户现有数据。若需要修改 ACL，由部署指南说明对应 dataset 和运行身份。

计划配置项包括 Web 端口、RPC 地址、RPC secret、UID／GID、时区和下载根目录。最终变量名称在 P0 固化，提供已验证的示例值；支持文件形式读取 secret，避免依赖命令行明文凭据。

交付文件：

- Dockerfile、`compose.yaml` 和 `.env.example`，用于常规 Docker 主机。
- 独立 TrueNAS YAML 模板：预构建的固定版本镜像、绝对 `/mnt/<pool>/<dataset>` 路径，不依赖 `build`、仓库文件或外部 `.env` 自动加载。
- 部署指南：通过 Apps → Custom App → Install via YAML 安装，替换模板路径、身份、端口和密钥后部署。
- 备份／恢复说明：SQLite 一致性备份、应用配置和 aria2 会话；下载 dataset 按用户存储策略快照。
- 升级／回滚说明：固定镜像标签，升级前备份，记录数据库迁移；不假设旧版本能够读取新 schema。

健康检查区分应用存活和引擎可用性：aria2 离线时 Web 仍可显示诊断，不能反复重启掩盖 RPC 故障。容器正确处理 SIGTERM，aria2 在停止宽限期内保存会话。

兼容范围：TrueNAS SCALE 24.10+ 的 Docker Apps 平台；发布时列出实测版本。CORE、旧 Kubernetes Apps、应用商店上架均不属于首版承诺。若开发环境没有 TrueNAS 主机，Docker 检查不能代替 TrueNAS 验收，发布状态须标记待验证。

## 5. 分阶段实施与验收

以下按单人全职开发粗估，共 18–27 个工作日，不含未获得测试设备的等待时间。每个阶段完成后根据实际结果调整。

| P0：设计与契约 | 页面规格、设计变量、状态映射、API 和部署配置清单     | 明确所有首版操作的启用条件、错误反馈和持久化归属                  | 2–3 天 |

## 6. 验证与发布门槛

- 单元测试聚焦状态归一化、选项校验、路径边界和任务关系；集成测试使用真实 aria2 与可控下载源。
- 端到端覆盖 URL 下载、Magnet 元数据衔接、种子选文件、批量部分失败、登录过期、引擎断线和重连。
- 使用受控的大文件及限速下载源验证容器重启后的断点续传；同时验证 `.aria2` 控制文件、会话文件和历史记录。
- 使用约 1,000 个模拟任务检查虚拟列表和更新频率，记录测试设备与指标；避免一次更新导致整表重绘或选中状态跳动。
- 适配桌面 Chrome、Firefox、Safari，以及移动 Safari／Chrome；检查图标可访问名称、焦点、触摸入口和对比度。
- Docker 检查配置解析、两个目标架构启动、非 root 写入、健康状态、持久卷恢复；验证 aria2 端口未意外公开。
- TrueNAS 实机验证全新 dataset 安装、ACL 不匹配提示、容器重启、下载文件访问、应用升级和从备份恢复，记录系统版本及步骤。
- 发布前完成类型检查、lint、生产构建及关键测试；文档仅提供确实存在且验证过的命令、镜像和配置。

## 7. 风险与后续范围

aria2 的完成历史和 Magnet 任务关系需要应用层补齐；不能把引擎会话文件当完整数据库。NAS 的 UID／GID 与 ACL 不匹配是主要部署风险，必须提供实际诊断和验证步骤。纯 WebSocket 通知不足以维持列表一致性，因此保留轮询和重连全量校准。

后续按使用反馈安排 RSS 订阅、计划限速、多实例、深色主题及通知。BT 搜索涉及独立的数据源与维护成本，不纳入首版。正式名称、许可证和发布镜像仓库在首次发布前确认，不影响当前界面和架构规划。
